# 商品搜索优化说明

## 一、优化目标

本次优化商品列表接口的关键词搜索能力：

```http
GET /products?keyword=关键词
```

优化前，搜索框输入内容只会作为一个完整字符串，在商品标题和商品描述中做模糊匹配。

优化后，搜索支持：

- 按商品标题匹配；
- 按商品描述匹配；
- 按商品分类标签名匹配；
- 输入多个关键词时，按空格、中文逗号、英文逗号、分号拆分后分别匹配；
- 不再要求用户输入完整连续文本。

## 二、原有搜索逻辑

原逻辑只匹配商品表中的两个字段：

```sql
title LIKE '%keyword%'
OR description LIKE '%keyword%'
```

因此：

- 输入 `教材` 可以匹配 `高数教材`；
- 输入 `高数` 可以匹配 `高数教材`；
- 输入 `高数 教材` 会被当作完整字符串 `%高数 教材%`，如果标题或描述中没有连续出现这段文本，就无法匹配；
- 输入分类标签名，如 `数码`、`教材资料`，只有商品标题或描述里包含这些字才会命中，不能直接按分类名搜索。

## 三、优化后的搜索逻辑

优化后，商品列表查询会关联分类表：

```sql
FROM products p
LEFT JOIN categories c ON c.id = p.category_id
```

关键词匹配范围变为：

```sql
p.title LIKE ?
OR p.description LIKE ?
OR c.name LIKE ?
```

关键词会先拆分。支持以下分隔符：

```text
空格
英文逗号 ,
中文逗号 ，
英文分号 ;
中文分号 ；
```

例如用户输入：

```text
高数 教材
```

后端会拆成：

```text
高数
教材
```

然后分别要求每个关键词都能在标题、描述或分类名中命中。

## 四、搜索示例

### 4.1 单关键词搜索

```http
GET /products?keyword=教材
```

可以匹配：

- 标题包含 `教材` 的商品；
- 描述包含 `教材` 的商品；
- 分类名包含 `教材` 的商品。

### 4.2 分类标签名搜索

```http
GET /products?keyword=数码
```

如果分类名为 `数码产品`，则该分类下的在售商品可以被搜索出来。

### 4.3 多关键词搜索

```http
GET /products?keyword=高数 教材
```

可以匹配：

- 标题中同时包含 `高数` 和 `教材` 的商品；
- 描述中同时包含 `高数` 和 `教材` 的商品；
- 标题、描述、分类名组合后能同时命中这两个词的商品。

### 4.4 逗号分隔搜索

```http
GET /products?keyword=高数，教材
```

等价于：

```http
GET /products?keyword=高数 教材
```

## 五、保留的筛选规则

本次只优化关键词搜索，不改变其他筛选逻辑。

仍然保留：

- 只展示 `ON_SALE` 且未删除商品；
- `categoryId` 精准筛选分类；
- `conditionLevel` 精准筛选成色；
- `minPrice`、`maxPrice` 价格区间筛选；
- `sort` 排序方式。

示例：

```http
GET /products?keyword=教材&categoryId=1&conditionLevel=九成新&sort=price_asc
```

含义：

- 关键词匹配标题、描述或分类名中的 `教材`；
- 同时要求商品分类 ID 为 `1`；
- 同时要求成色为 `九成新`；
- 按价格从低到高排序。

## 六、涉及文件

后端：

```text
backend/internal/product/repository.go
```

本次未修改前端文件。前端仍通过原有 `keyword` 参数调用商品列表接口，搜索能力由后端增强。

## 七、建议验证场景

本次按要求未运行代码，后续可按以下场景手动验证：

1. 输入商品标题中的一个词，可以搜索出商品。
2. 输入商品描述中的一个词，可以搜索出商品。
3. 输入分类标签名，如 `教材`、`数码`、`生活用品`，可以搜索出对应分类下商品。
4. 输入多个关键词，如 `高数 教材`，可以搜索出同时命中这些词的商品。
5. 输入逗号分隔关键词，如 `高数，教材`，结果与空格分隔一致。
6. 搭配 `categoryId`、`conditionLevel`、价格区间、排序参数时，筛选结果仍符合原有规则。

## 八、注意事项

- 当前搜索不是全文索引，也不是智能语义搜索。
- 当前不支持错别字、拼音、同义词自动扩展。
- 多关键词之间采用“同时满足”的规则，适合缩小搜索范围。
- 如果希望更宽松地匹配任意一个关键词，可以后续将多关键词逻辑从 `AND` 调整为 `OR`。
